# Kymeta

> Kymeta Corporation builds electronically steered, flat-panel metamaterial satellite antennas
> (the u8 terminal family and the Kestrel u5) and the Kymeta Connect service platform that runs
> behind them, for military and government, maritime, land-mobile, energy and humanitarian users
> needing multi-orbit GEO/LEO connectivity on the move. Kymeta operates a first-party API host and
> its own OAuth 2.0 / OpenID Connect identity provider, but publishes no public developer program,
> no API reference and no machine-readable API contract.

This file was generated by API Evangelist from publicly reachable Kymeta surfaces on 2026-08-23.
It is an independent third-party profile, not a Kymeta publication.

## What is and is not available to an agent

- There is **no OpenAPI, Swagger, GraphQL SDL, AsyncAPI, WSDL or Protobuf** published by Kymeta at
  any probed location. This was checked against every Kymeta host, not just the website.
- There is **no MCP server, no A2A agent card, no llms.txt of Kymeta's own, and no SDK** in any
  public package registry.
- `https://api.kymeta.io` is a real, live, first-party API host. It answers unauthenticated on
  three endpoints only — `/health`, `/version`, `/status` — and returns HTTP 404 with an empty
  body on every other path probed. Its CORS policy advertises GET, PUT, POST, DELETE, PATCH and
  OPTIONS, so a write surface exists, but none of it is documented.
- Everything functional is gated behind Kymeta's OAuth 2.0 server at `https://access.kymeta.io`.
- Product documentation and software-release notices require a Kymeta Access Portal account.
- Kymeta's `robots.txt` disallows GPTBot, Google-Extended and PerplexityBot from the whole
  corporate site, so much of the human-readable material is deliberately out of scope for
  AI crawlers.

## Machine-readable documents Kymeta actually publishes

- [OpenID Connect discovery — Kymeta Access](https://access.kymeta.io/.well-known/openid-configuration): the only machine-readable API contract Kymeta publishes. Issuer `https://access.kymeta.io`, eleven scopes including a named `partners-api` scope.
- [JWKS — Kymeta Access](https://access.kymeta.io/.well-known/openid-configuration/jwks): signing keys for the above.
- [Platform status roll-up](https://api.kymeta.io/status): per-service HTTP code and build version for the ten Kymeta Connect services.
- [Platform version](https://api.kymeta.io/version): gateway build number.

## APIs

- [Kymeta Connect Platform API](https://www.kymetacorp.com/support/app): base `https://api.kymeta.io`. Services named by Kymeta's own status endpoint: accounts, activityLogger, enterpriseBroker, fileStorage, logicApp, remoteMetrics, scheduler, subscriptions, users, devices. No published contract.
- [Kymeta Access Identity](https://access.kymeta.io/): base `https://access.kymeta.io`. OAuth 2.0 / OpenID Connect authorization server. Grants: authorization_code (PKCE S256), client_credentials, refresh_token, implicit, device_code.
